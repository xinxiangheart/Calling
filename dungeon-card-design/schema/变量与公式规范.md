# 变量与公式规范

这是**契约文档**。Python 导出脚本、Unity 卡树编辑器、以及未来的 Unity 战斗系统
都必须按这份文档实现，否则三方会对不上。

---

## 1. 一张卡的「值」有四种来源

| 写法 | 名称 | 谁提供值 | 例子 |
| --- | --- | --- | --- |
| `伤害 = 2` | 卡内常量 | 策划（设计期已知） | 三级共用同一个值 |
| `伤害_Lv2 = 3` | 卡内升级值 | 策划（设计期已知） | 只在 Lv.2 生效 |
| `$力量`、`$target.护甲` | 运行时量 | 游戏运行时 | 设计期只知道名字 |
| `$力量 * 倍率` | 派生算式 | 运行时计算 | 设计期只知道算法 |

前两种是「卡内变量」，后两种是「运行时引用」。区分办法是**值里有没有 `$`
或运算符**，策划不用手动声明来源。

## 2. 语法

### 2.1 变量行

```
【变量】名字 = 值
```

`值` 的形态自动判定，规则按顺序：

1. 值是 `无` / `none` / `-` 这类占位写法 → **字面量**（当作没填）
2. 值被引号包起来（`"..."` 或 `'...'`）→ **强制字面量**，引号会被剥掉
3. 值里含 `$`、运算符（`+ - * / ( )`）→ **算式**
4. 值里含裸标识符（字母/汉字）→ **算式**（这样 `攻击` 会被当成变量名，
   想写文字就加引号）
5. 其余 → **字面量**

### 2.2 变量名

- `名字` → 三个等级共用（常量的标准写法）
- `名字_Lv1` / `名字_Lv2` / `名字_Lv3` → 该等级专用
- 取值顺序：**先找 `名字_LvN`，找不到再回退 `名字`**，都没有则取不到值
- 同一个键定义两次 → 错误

### 2.3 效果文本里的花括号

`【效果】` 里的 `{...}` **只能写一个变量名**，不能写算式：

```
造成 {伤害} 点伤害          ✓ 变量名
造成 {伤害 * 2} 点伤害      ✗ 花括号里不能写算式
```

要显示算出来的数字，就在【变量】里定义一个新变量，把算式写在它的值里，
再在效果里引用那个变量名：

```
【变量】倍率_Lv1 = 1.0; 倍率_Lv2 = 1.5; 倍率_Lv3 = 2.0
【变量】总伤害_Lv1 = 倍率 * $player.力量
【效果】造成 {总伤害} 点伤害
```

这样「算法」集中在【变量】里，「文案」保持在【效果】里，各管各的。

花括号里的名字按 §2.4 的顺序查找：先本卡变量，再运行时量注册表。
半角 `{}` 和全角 `｛｝` 等价。

### 2.4 名字怎么找（花括号和算式共用同一套顺序）

按顺序找，**先命中先赢**：

1. **本卡变量**（等级感知：`名字_LvN` → `名字`）
2. **运行时量注册表**：允许省略 `$`，等价于 `$player.名字`；
   但如果这个名字在多个来源里都存在（如 `护甲` 在 `player` 和 `target` 里都有），
   必须写全 `$target.护甲`，否则报错
3. 都没找到 → 错误

### 2.5 运算符

```
expression := term (('+' | '-') term)*
term       := factor (('*' | '/') factor)*
factor     := '-' factor | primary
primary    := number | '$' reference | name | '(' expression ')'
reference  := [source '.'] name
```

- 只支持 `+ - * /`，**不支持 `%`、`^`、`×`、`÷`**（需要时再扩）
- 乘号**必须写 `*`**，除号必须写 `/`。写 `×` 或 `÷` 会报错并提示改正
- `×` 只属于**显示层**：UI 展示时把 `*` 渲染成 `×`，但**数据里必须写 `*`**
- 数字：`2`、`3.5`、`0.8`
- 负数用一元 `-`，如 `-2`

> 注意：`X`（英文字母 x）和 `×` 都**不是**乘号。写乘法只能用 `*`。
> 之所以不让 `×` 直接进数据：UI 会把 `*` 显示成 `×`，如果两种写法都收，
> 数据里就会同时存在两种乘号，比对和查找会变得不可靠。

## 3. 运行时量注册表

文件：`dungeon-card-design/schema/runtime_vars.json`

```json
{
  "default_source": "player",
  "sources": [
    {
      "name": "player",
      "label": "玩家",
      "vars": [
        { "name": "力量", "type": "int", "sample": 4, "desc": "决定武器装备门槛" }
      ]
    }
  ]
}
```

- `type`：`int` / `float` / `text`
- 当前共 **36 个量**：`player` 13 / `target` 7 / `battle` 4 / `run` 11 / `meta` 1
  （这份名单已定稿，后续可增删；改动同样算改契约）
- `sample`：**只给编辑器预览当默认值**，运行时不用
- 这份文件是**设计期契约**，也是未来战斗系统的 checklist：
  这里列的每个量，运行时都必须能取到
- 改这份文件 = 改契约，要同步战斗代码

## 4. 校验规则

| # | 规则 | 级别 |
| --- | --- | --- |
| 1 | 效果引用了 `{X}`，卡内没定义、注册表里也没有 | 错误 |
| 2 | 变量定义了但没有任何算式/效果引用它 | 警告 |
| 3 | 同一个变量键定义了两次 | 错误 |
| 4 | 声明 `int` 但字面量不是整数 / 声明 `float` 但不是数字 | 错误 |
| 5 | 字面量超出 `min` / `max` | 错误 |
| 6 | `类型` 不是 `int` / `float` / `text` | 警告 |
| 7 | `_LvN` 只覆盖了部分等级 | 警告 |
| 8 | **算式语法错误**（括号不配、运算符残缺、有多余字符） | 错误 |
| 9 | **算式里引用了未定义的裸名字** | 错误 |
| 10 | **`$来源` 不在注册表里 / `$来源.名字` 不存在** | 错误 |
| 11 | **`$名字` 简写在多个来源里都能匹配（有歧义）** | 错误 |
| 12 | **变量之间循环引用**（A 用 B，B 又用 A） | 错误 |
| 13 | 算式依赖的某个变量在 Lv.N 取不到值 → 该等级无法渲染 | 警告 |
| 14 | 算式结果类型与声明的 `type` 冲突 | 错误 |
| 15 | **花括号里写了算式**（含运算符、空格、多个名字） | 错误 |
| 16 | **算式里出现 `×` / `÷` / `X`**（不是合法运算符） | 错误，提示改用 `*` `/` |

规则 4 / 5 / 14 只对**字面量**校验；算式的结果值设计期算不出来，
所以只校验它的引用（规则 8~13）。

## 5. 导出 JSON 新增字段：`bindings`

Python 导出时，为每张卡生成一个 `bindings`，把「这句话里哪些是变量、哪些是原样文字、
每个等级分别是多少」全列出来，这样 **Unity 运行时不用重新实现一遍解析规则**。

```json
"bindings": {
  "levels": ["1", "2", "3"],
  "variables": [
    { "key": "伤害", "kind": "literal",
      "levels": { "1": "2", "2": "3", "3": "4" } },
    { "key": "总伤害", "kind": "formula",
      "refs": ["伤害"], "runtime_refs": ["player.力量"] }
  ],
  "effect_segments": [
    { "kind": "text", "content": "造成 " },
    { "kind": "card", "name": "伤害", "levels": { "1": "2", "2": "3", "3": "4" } },
    { "kind": "text", "content": " 点伤害" }
  ],
  "runtime_deps": [
    { "source": "player", "name": "力量", "type": "int" }
  ]
}
```

`effect_segments[].kind` 取值：

- `text`：原样文字，内容在 `content`
- `card`：卡内变量，带 `name` 和各等级的值（**没有** `source`）
- `runtime`：运行时量，带 `source` / `name` / `type` / `sample`
- `error`：解析失败的占位符，带 `name`，`content` 保留 `{xxx}` 原文，渲染成红色

`error` 段是**给 UI 用的信号**：写错的占位符不会被降级成 `text`，
也不会因为「整句看起来都是文字」而把 `bindings` 整个省掉——否则 Unity 拿不到
「这里有问题」的标记，只能去翻 warnings 文本。

`bindings.variables[]` 的字段是 `key` / `kind` / `levels`，
`kind = formula` 时另外带 `refs`（本卡变量）和 `runtime_refs`（`来源.名字`）。

`bindings` 是**派生字段**：Unity 存盘时丢弃，每次导出重新生成。
卡内变量、运行时量、错误都只在 `effect_segments` 里表达，文本里不额外插标记。

## 6. 卡面着色约定

预览和未来的卡面渲染都用同一套颜色，让「这个数字会不会变」一眼可见：

| 内容 | 颜色 | 含义 |
| --- | --- | --- |
| 卡内变量 | `#44DD44` 绿 | 升级会变，设计期已知 |
| 运行时量 | `#FFAA00` 橙 | 战斗中随时会变 |
| 普通文字/数值 | 默认色 | 不会变的字 |
| 解析失败/未定义 | `#FF4444` 红 | 有问题的占位符 |

色值只写在 `CardSegmentPalette`（`Assets/Scripts/CardTree/CardTreeData.cs`）一处，
面板预览、节点视图、将来的运行时卡面都从这里取色，避免三处各写一套。

## 7. 完整例子

```
【卡名】重击
【品级】普通
【类别】攻击
【效果】造成 {伤害} 点伤害，获得 {格挡} 点护甲
【变量】伤害_Lv1 = 2; 伤害_Lv2 = 3; 伤害_Lv3 = 4
【变量】格挡_Lv1 = 3; 格挡_Lv2 = 4; 格挡_Lv3 = 5
【获取】初始
【设计意图】基础单次高伤卡。
```

```
【卡名】狂怒斩
【品级】稀有
【类别】攻击
【效果】造成 {总伤害} 点伤害，对自己造成 {反噬} 点真实伤害
【变量】倍率_Lv1 = 1.0; 倍率_Lv2 = 1.5; 倍率_Lv3 = 2.0
【变量】总伤害_Lv1 = 倍率 * $player.力量
【变量】反噬 = 2
【获取】由「重击」合成进化
【设计意图】力量放大卡，配合力量成长。
```

注意这个例子的分工：**算式全在【变量】里**，【效果】里只有 `{变量名}`。
`倍率_Lv1 = 1.0` 会在 Lv.1 生效，所以 Lv.1 打出去是「力量 × 1.0」，
Lv.3 是「力量 × 2.0」——成长曲线靠变量升级实现。

```
【卡名】天坠
【品级】传说
【类别】攻击
【效果】造成 {总伤害} 点伤害，无视护甲，必中
【变量】基础 = 5
【变量】总伤害 = 基础 + $target.碎甲层数 * 2
【获取】传说宝箱
【设计意图】终极核弹。
```

## 8. 兼容性

- **旧的卡不用改**：`{力量}` 这种写法仍然有效。只要 `力量` 在注册表里，
  它就自动被认成运行时量，不再报「引用了但没定义」。
- **纯字面量不受影响**：`2`、`3.5`、`无` 的判定规则和以前完全一样。
- **`×` 不再当乘号**：老写法里如果用了 `×`，现在会报错并提示改成 `*`。
  这是本次唯一的破坏性改动，代价换来的是「数据里只有一种乘号」。
- **花括号里的算式不再被接受**：老写法 `{伤害 * 2}` 现在会报错，
  改成在【变量】里定义 `总伤害 = 伤害 * 2`，效果里写 `{总伤害}`。
- **`【变量】` 的 JSON 结构向后兼容**，旧文件读进来照常能存回去。
